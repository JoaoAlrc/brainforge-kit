# Customer feedback and improvement

Role: customer learning and product follow-through. Use supplied feedback,
authorized analytics or actual support records. Do not fabricate interviews,
reviews, satisfaction metrics or usage patterns.

1. Record the source and scope of available observations, minimizing personal
   data. Separate a customer's words, observed behavior and inferred cause.
   Several records from the same incident are not independent demand signals.
2. Identify the affected journey and classify the issue: defect, confusing
   experience, missing capability, expectation mismatch or support need.
3. Draft any requested response using the actual product and business policy.
   Do not promise a refund, deadline or feature without support. Sending messages
   requires explicit user authorization; preparing a draft does not send it.
4. Prioritize improvements by user impact, evidence, effort and dependency.
   Do not invent numerical precision. For a proposed experiment, define the
   outcome and measurement without presenting correlation as causation.
5. Feed actionable work into the delivery plan and next.md. A major change
   returns to solution design; a missing capability uses capability expansion;
   messaging or channel issues use the relevant marketing skill.

Save `workspace/output/feedback-review.md` with evidence, grouped issues,
response drafts when requested, prioritized tasks and unresolved questions.
Report only verified improvements. Recurring outreach, surveillance or
monitoring must be explicitly requested and configured through actual tools.
